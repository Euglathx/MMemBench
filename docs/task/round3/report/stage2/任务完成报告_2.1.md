## 问题背景

### Phase 1 发现的问题
根据 Phase 1 Task 1.1 的验证报告:

- **46.1% 的 turns (150/325)** 的 `images_sent` 字段为空
- 模型回复 "I'm unable to view images directly"
- 所有受影响 turns 的评估结果完全无效
- 问题与时间相关(2月1日运行失败,2月2日运行成功)
- 原始代码缺乏错误日志和验证机制

### 根本原因
原始的 `_get_images_for_turn()` 方法存在脆弱的路径解析逻辑:
- 工作目录不匹配时会失败
- 搜索策略有限
- 没有错误日志
- 找不到图像时静默失败

## 解决方案设计

### 设计原则 (符合 Task 2.1 要求)
- ✅ **最小侵入性**: 不改变现有接口
- ✅ **向后兼容**: 能处理旧的 run logs
- ✅ **可配置性**: 通过 `verbose` 标志控制行为
- ✅ **可测试性**: 包含全面的单元测试

### 多策略路径解析

新实现按顺序使用4种解析策略:

```
策略1: 直接路径 (相对于当前工作目录)
    └── 检查路径是否直接存在

策略2: 绝对路径检查
    └── 验证是否为绝对路径且存在

策略3: 搜索 generated_tasks_v2/run_*/images
    └── 优先检查较新的 run 目录(按修改时间)
    └── 尝试带/不带 "images/" 前缀

策略4: 项目根目录的常用目录
    └── 搜索 images/, data/images/, assets/images/
    └── 尝试仅使用文件名作为回退
```

## 实现细节

### 修改的文件
- [src/simulator/strategic_simulator.py](../../../../../../src/simulator/strategic_simulator.py)

### 新增/增强的方法

#### 1. `_get_images_for_turn(self, action: str) -> List[str]`
增强版本包含:
- 全面的日志记录 (INFO/DEBUG/WARNING/ERROR 级别)
- 每个图像的解析状态报告
- 解析汇总统计
- 可选的 RuntimeError 验证(verbose 模式)

**关键特性**:
```python
# 记录每个图像的解析尝试
# 跟踪失败的图像
# 验证至少有一些图像成功解析
# 在 verbose 模式下,如果所有图像都失败则抛出 RuntimeError
```

#### 2. `_resolve_single_image_path(self, img_rel_path: str, img_idx: int) -> Optional[str]`
新方法,实现多策略解析:
- 4种回退策略
- 每个图像的详细日志
- 返回解析后的绝对路径或 None

#### 3. 修改 `step()` 方法
在调用目标模型前添加验证:
```python
# 如果期望有图像但无法解析,发出警告
if self.task_state.images and not images_to_send:
    warning_msg = (
        f"[WARNING] Task {self.task_state.task_id} 期望 "
        f"{len(self.task_state.images)} 张图像但未能解析。"
    )
    logger.warning(warning_msg)
```
